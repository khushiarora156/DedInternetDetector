# Dead Internet & Fake Engagement Detector

A robust, explainable, and multi-threaded Java console application designed to detect automated bot networks, fake engagement patterns, and "Dead Internet" synthetic activity across social media account datasets.

Developed as a college software engineering project demonstrating core **Object-Oriented Programming (OOP)**, **Design Patterns (Strategy & Coordinator)**, **Java Collections Framework**, **Multithreading Concurrency**, **Defensive Validation**, **File I/O**, and **Automated Testing**.

---

## 1. Problem Statement

The **"Dead Internet Theory"** posits that an increasingly substantial portion of internet traffic, social media comments, and digital interactions are generated by autonomous bots, engagement farming syndicates, and click farms rather than organic humans.

Unchecked automated activity distorts public discourse, manipulates market sentiment, skews advertising metrics, and deceives everyday users. There is an urgent need for transparent, explainable, and lightweight audit tools capable of screening account records and identifying statistically anomalous behaviors without relying on opaque black-box algorithms or proprietary social media APIs.

---

## 2. Project Objectives

- **Automated Anomaly Detection**: Identify bot-like patterns including hyper-velocity burst commenting, copy-pasted comments, unnatural follower/following ratios, and synthetic engagement rates.
- **Explainable Scoring**: Compute a normalized risk score between $0$ and $100$ where every point is directly attributable to explicit, inspectable heuristic rules.
- **Academic Rigor**: Serve as a high-quality showcase of Java concepts for undergraduate computer science pair/team programming, code defense, and viva examinations.
- **High Performance**: Utilize Java's `ExecutorService` and `Callable` concurrency framework to process account datasets simultaneously across multiple CPU threads.
- **Zero External Dependencies**: Operates entirely offline with standard Java standard libraries, requiring no external databases, web servers, or third-party web scraping APIs.

---

## 3. Scope & Limitations

> [!IMPORTANT]
> **Ethical Principle & Non-Definitive Stance**:
> A high risk score indicates statistical suspicion, **NOT** definitive proof that an account is a bot. The application serves strictly as an auditable decision-support system to guide human moderation and triage.

- **Offline Analysis**: Operates over structured CSV records and manual console input. It does not initiate live HTTP requests or violate platform Terms of Service.
- **Synthetic Heuristics**: Detection relies on observed post metrics, timestamps, and comment frequency rather than deep network packet inspection or biometric telemetry.

   *(Executes 15 comprehensive unit and edge case tests)*

2. **Launch the Console Application**:
   ```powershell

   ```

---

### Option B: Using Standard Java Commands (`javac` / `java`)

1. **Compile Application Classes**:
   ```powershell
   New-Item -ItemType Directory -Force -Path target/classes
   javac -d target/classes (Get-ChildItem -Path src/main/java -Recurse -Filter *.java | ForEach-Object { $_.FullName })
   ```

2. **Compile and Run Tests**:
   ```powershell
   New-Item -ItemType Directory -Force -Path target/test-classes
   javac -cp target/classes -d target/test-classes src/test/java/com/detector/TestHarness.java
   java -cp "target/classes;target/test-classes" com.detector.TestHarness
   ```

3. **Run Application**:
   ```powershell
   java -cp target/classes com.detector.main.Main
   ```

---

### Option C: Using Apache Maven (When `mvn` is Configured)

1. **Compile and Test**:
   ```powershell
   mvn clean test
   ```

2. **Package and Run Executable JAR**:
   ```powershell
   mvn package
   java -jar target/dead-internet-detector-1.0.0.jar
   ```

## 8. Detection Heuristics & Scoring

| Rule Name | Checked Condition | Default Threshold | Weight | Viva Defense Rationale |
| :--- | :--- | :--- | :---: | :--- |
| `NewAccountRule` | `accountAgeDays < threshold` | $< 30$ days | $+15$ pts | Disposable botnet accounts created for short-lived spam waves. |
| `RepetitiveCommentRule` | `repeated / totalComments >= threshold` | $\ge 50\%$ | $+20$ pts | Templated, copy-pasted comments. Protected by $5$ comment min sample. |
| `UnusualEngagementRule` | `(likes + comments) / followers * 100` | $\ge 25.0\%$ | $+15$ pts | Organic engagement rarely exceeds 5%. Protects zero-follower edge cases. |
| `RapidActivityRule` | `commentsInTenMinutes > threshold` | $> 20$ cmts | $+15$ pts | Velocity exceeds physical human reading, typing, and posting limits. |
| `SuspiciousFollowRatioRule` | `following / followers >= threshold` | $\ge 10.0\text{x}$ | $+15$ pts | Mass follow churners. Protects personal accounts with min 150 following. |

### Classification Tiers:
- **0 – 29**: `LOW` (Minimal or no suspicion)
- **30 – 59**: `MEDIUM` (Moderate suspicion, queue for audit)
- **60 – 100**: `HIGH` (Strong bot indicators, multiple concurrent flags)

For mathematical formulations and threshold rationale, see [`docs/DETECTION_RULES.md`](docs/DETECTION_RULES.md).
